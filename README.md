# git-sentry

DSH 插件，用于集中管理本机上的 Git 项目。

## 它做什么

- 在一个面板里查看已导入项目的工作区状态、当前分支与领先/落后提交数
- 对单个项目执行拉取、提交、推送
- 按需自动同步：无冲突时自动更新，有冲突时仅提示，不擅自替你处理

## 当前状态

**第一期：UI 原型（进行中）**

界面先行——按钮可点击，但不执行真实的 Git 操作，点击后以浮窗提示代替。
此阶段不读取仓库、不持久化数据、不启动定时器，刷新页面即回到初始状态。

## 已确定的设计约束

- **拉取来源与推送目标分离**：拉取跟随 `origin/HEAD`，推送发往 `origin/<当前分支>`
  （合并二者的做法在服务器分支上会安静地失效，或把服务器改动推上默认分支）
- **服务器上的改动走独立分支**，不直接落在远程默认分支
- **不代管凭据**：沿用系统 Git 配置与凭据助手
- **不做** `stash` / `checkout` / `reset` / `--force`
- 同一仓库的同步操作**串行**执行
- **非交互保护**：命令带 `GIT_TERMINAL_PROMPT=0`，SSH 走 `BatchMode=yes`

## 仓库结构

插件以 DSH bundle 形式开发，源码即包本体：

| 文件 | 作用 | 当前状态 |
| --- | --- | --- |
| `package.json` | 包声明与 `dsh` 元数据 | 已就位 |
| `cordis.patch.yml` | 挂载入口（id: `git-sentry`） | 已就位 |
| `index.js` | Host 侧逻辑 | 空实现，仅导出 `apply` |
| `client.js` | 浏览器侧 UI | 空实现，不注册任何 slot |
| `locale/zh.json`、`locale/en.json` | 文案 | 仅 `meta` |
| `icon.svg` | 图标 | 已就位 |

## 骨架的边界

当前 `client.js` **刻意什么都不渲染**。这样 bundle 能被安装并挂载成功，同时不把尚未
定稿的界面结构固化进代码——第一期 UI 的落点需要按各 slot 的实际 props 决定，属于
开发阶段的工作。
