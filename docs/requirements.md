| 项 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 定稿时间 | 2026-10-14 |
| 状态 | 已与用户逐条确认 |

---

## 1. 背景

用户平时在**公司**和**家里**两处做项目，代码通过 GitHub 同步。DSH 部署在一台**服务器**上，
服务器上保存着这些项目的工作副本。

由此产生的三个具体痛点：

1. 服务器上没有图形化 git 客户端。要知道哪个项目有变化，得逐个 `cd` 进仓库、逐个敲 `git status`。
2. 想确认"公司推的新提交到了没有"、"服务器这边的改动推没推出去"，需要在多个仓库之间反复切换查看。
3. 希望服务器上的副本能自动跟进远程的新提交，而不是每次登上去手动拉。

## 2. 目标

做一个 DSH 插件，让用户**在一个面板里**完成三件事：

- 看到所有已导入项目的 git 状态
- 用按钮完成拉取 / 提交 / 推送
- 按项目配置的自动同步，把远程的新提交合进来

## 3. 使用环境与范围

| 项 | 说明 |
| --- | --- |
| 使用者 | 用户本人。单人使用，**无多用户、无权限体系**需求 |
| 部署形态 | 插件运行在服务器上的那台 DSH 实例里，界面通过浏览器访问 |
| 被管理对象 | 服务器**本机文件系统**上的 git 仓库 |
| 管理范围 | **仅插件所运行的那个 DSH 实例所在的机器**。不跨机器管理 |
| 远端 | GitHub，HTTPS 协议，凭据由 `gh auth git-credential` 提供 |
| 分支模型 | 服务器上的改动走**独立分支**；远程主分支承载公司/家里的提交 |

## 4. 功能需求

### FR-01 项目导入

| 项 | 要求 |
| --- | --- |
| 触发方式 | 用户**主动点击**"导入项目"按钮 |
| 目录选择 | 复用 DSH 已有的目录选择能力，不自建选择器 |
| 多仓库处理 | 选中的目录若含多个 git 仓库，**列出子仓库供用户勾选** |
| 校验 | 仅接受确实是 git 仓库的路径 |
| 结果 | 写入持久化项目清单 |
| **明确不做** | 开机/定时自动扫描目录并纳管。导入永远是显式动作 |

### FR-02 项目清单

- 持久化保存在 **Host 侧**，客户端不另存一份，避免两边状态漂移。
- 支持移除已导入的项目（只从清单移除，**不删除磁盘上的仓库**）。

### FR-03 状态显示

每个项目至少展示：

| 字段 | 说明 |
| --- | --- |
| 项目名 / 路径 | 显示名可自定义，路径用于定位 |
| 当前分支 | 例如 `MintDev`、`main` |
| 同步来源 | 拉取时合入哪个引用，例如 `origin/HEAD` |
| 推送目标 | 推送发往哪个引用，例如 `origin/MintDev` |
| 领先 / 落后 | **一律相对同步来源**计算的提交数，形如 `↑2 ↓5`。**不使用 `@{upstream}` 作为基准**（见 `D-09`、`R-01`） |
| 相对推送目标 | 推送目标是否存在、是否领先（能否快进推送）。**推送安全性直接依赖此值** |
| 工作区状态 | 干净 / 有 N 个未提交改动 |
| 最后 fetch 时间 | 上次成功获取远程引用的时间。**领先 / 落后均以此为前提**，超时未刷新时应在界面上体现 |
| 最后同步 | 时间 + 结果（成功 / 跳过 / 冲突 / 不可达） |

> **同步来源与推送目标必须分两栏显示。** 见 `decisions.md` 的 `D-09`。

### FR-04 手动拉取

- 从**同步来源**拉取，合入当前分支。
- 合并行为遵循 `plan.md` 中的自动同步决策矩阵（手动与自动用同一套逻辑）。

### FR-05 手动提交

| 项 | 要求 |
| --- | --- |
| 范围 | **全量提交**工作区所有改动，不做部分文件勾选 |
| 前置校验 | 提交前校验该仓库的 `user.name` / `user.email` 是否已配置；缺失则**中止并提示用户自行在服务器上为该仓库配置身份**，插件不代设、不写任何 git 配置 |
| 提交前 | **列出将要提交的文件清单**供用户确认 |
| 提交信息 | 由用户填写 |
| **明确不做** | 让 agent 根据改动生成提交信息草稿 |

### FR-06 手动推送

| 项 | 要求 |
| --- | --- |
| 目标 | 固定 `origin/<当前分支名>`，**不是**同步来源 |
| 确认 | 推送前需要用户确认 |
| 远程无同名分支 | 默认**自动创建并推送**；设置页有开关可关闭，关闭后改为提示 + 显式确认按钮 |

### FR-07 自动同步

- 轮询驱动。**默认间隔 60 秒**，设置页可调，允许整体关闭。
- 支持**逐项目开关**。
- 行为遵循 `plan.md` 中的自动同步决策矩阵。

### FR-08 设置页

| 配置项 | 默认值 |
| --- | --- |
| 轮询间隔 | 60 秒 |
| 逐项目自动同步 | 关（导入后由用户逐个开启） |
| 推送时若远程无同名分支则自动创建 | 开 |

### FR-09 对话工具暴露

- 上述 git 能力暴露为 agent 工具，**参数与语义和面板按钮完全一致**。
- **插件自身不主动调用 agent**——不由插件发起任何模型请求。

### FR-10 同步结果事件点

- 把每次同步的结果（合入成功 / 跳过 / 冲突 / 远程不可达）作为**可订阅的事件**发出。
- 本期**不做通知界面**，目的只是为将来接入 Telegram Bot 留出接口，
  届时外部消费者订阅即可，插件本身不需要改。

## 5. 非功能需求

| 编号 | 要求 | 理由 |
| --- | --- | --- |
| NFR-01 | 所有 git 子进程**非交互** | 服务器无人值守，等待输入会导致挂死 |
| NFR-02 | 每次 git 调用带**硬超时**，超时强制终止并记为失败 | 网络异常时 `fetch` 可能长时间不返回 |
| NFR-03 | **同一仓库经本插件的 git 操作串行**：插件自身发起的操作之间互斥。插件**不感知**用户在服务器终端发起的 git 操作；遇 `.git/index.lock` 存在时视为忙，**跳过本轮** | 避免自动同步与用户在面板上的手动操作互相踩踏 |
| NFR-04 | **失败隔离**：单个项目失败不影响其余项目 | 一个坏仓库不应让整个面板停摆 |
| NFR-05 | 合并失败后回滚到**合并前状态**；若合并期间工作区被外部修改（用户编辑文件、终端侧 git 操作），回滚可能不完整——此时**如实报告残留状态并要求用户确认**，不静默继续 | 不留半完成的合并状态，且不假装回滚一定成功 |
| NFR-06 | **不代管凭据** | 凭据配置属用户手动动作，插件不引导输入密钥 |
| NFR-07 | 不修改 profile 的 `package.json`，不在 profile 目录跑包管理 | 否则 DSH 升级会冲掉改动 |
| NFR-08 | 清单持久化归属 Host 侧 | 单一数据源，避免客户端状态漂移 |
| NFR-09 | 兼容性：冲突预判依赖 `git merge-tree --write-tree`（**≥ 2.38**）；低于此版本自动降级 | 服务器当前为 2.43，但插件不应假设环境 |

## 6. 明确的非目标

以下各项**已确认不做**，实现时不要顺手加进来：

| 非目标 | 说明 |
| --- | --- |
| 项目分组 | 第一期不做。项目在十几个以内时平铺更快，等确实放不下再按父目录自动分组 |
| 通知推送 | 本期不做。改为预留可订阅事件点（FR-10） |
| 跨机器管理 | 只管本机。将来若要管多机，作为新需求重新评估 |
| 凭据管理 | 不代管、不存储、不引导输入 SSH key / token |
| 破坏性 git 操作 | 不做 `stash` / `checkout` / `reset` / `--force` 推送 |
| 部分文件提交 | 提交永远全量（FR-05） |
| agent 生成提交信息 | 不做（FR-05） |
| 修改仓库 git 配置 | 不改 `~/.gitconfig`、不改仓库 `.git/config` |
| 自动推送 | 推送永远由用户显式触发 |

**待议（P3 再评估）**：diff 查看、提交历史、分支切换、批量操作、Webhook 触发替代轮询。

## 7. 验收标准

### 7.1 第一期（纯 UI 原型）

- [ ] 侧边栏出现常驻入口，点击可打开主面板
- [ ] 主面板按项目列出示例行，含分支、领先落后、脏标记、自动同步开关、行内三个按钮
- [ ] 右侧详情面板可打开，含状态摘要、待合入提交、冲突文件区、提交表单、推送按钮、同步记录
- [ ] 设置页可打开，三个配置项可见
- [ ] 每一处未实现的操作**点击后弹出提示浮层**，说明"该功能将来会做什么"，
      不假装成功、不静默无反应
- [ ] 界面标注"演示数据"徽标
- [ ] 不读 git、不存数据、不装定时器；**刷新页面后面板状态回到初始值**（这是预期行为）

### 7.2 第二期（自动同步）

- [ ] 轮询按配置的间隔运行，可整体关闭
- [ ] 无冲突时自动合入，用户未提交改动原样保留
- [ ] 会冲突时**不动工作区**，仅提示冲突文件
- [ ] 预判无冲突但实际冲突时，能回滚到合并前状态
- [ ] 回滚不完整时（合并期间工作区被外部修改）有明确提示，不静默继续
- [ ] 自动同步与手动操作并发时，自动同步跳过本轮

### 7.3 整体

- [ ] 服务器上无图形环境时，插件不会因 git 等待输入而挂死
- [ ] 单个项目操作失败，其余项目状态仍能正常刷新
- [ ] 交互式 shell 中没有出现任何未经用户点击的推送

## 8. 术语表

| 术语 | 含义 |
| --- | --- |
| 同步来源 | 拉取时从哪个引用合入，默认 `origin/HEAD`。**与推送目标无关** |
| 推送目标 | 推送发往哪个引用，固定 `origin/<当前分支名>`。**与同步来源无关** |
| 上游 | git 自身的 `@{upstream}` 概念。**本插件的设计中刻意不使用它作为同步依据**，原因见 `D-09` |
| 脏工作区 | 存在未提交的改动（已跟踪文件的修改，或未跟踪的新文件） |
